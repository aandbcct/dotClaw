# 运行放弃与工具展示：轻量开发方案

## 1. 范围

仅实现：①放弃可恢复运行；②审批卡片直接展示实际操作；③已有工具结果分类展示。

复用现有消息内过程、活动查询、审批接口及运行放弃能力。不增加数据库、任务队列、工具渲染插件框架或新的 SSE 类型。不修改模型调用、工具执行协议、磁盘格式。

本次“放弃”仅针对 `recoverable`：不是停止运行、拒绝审批、取消子任务或删除会话。后端当前放弃会删除检查点、保留运行记录，不能恢复；不会撤销已执行的工具副作用。

## 2. 放弃可恢复运行

### 后端

| 文件／对象 | 修改 |
|---|---|
| `channel/web/app.py` | 新增 `POST /api/v1/sessions/{session_id}/runs/{run_id}/abandon`，无请求体，成功返回现有活动响应 JSON，不使用 SSE |
| `bootstrap/session_interaction.py`：`SessionInteractionService`（会话交互服务） | `abandon_run(run_id, *, only_recoverable=False)` 增加可选参数并透传；Web 使用 `True`，既有调用默认行为不变 |
| `runtime/application/session_run_coordinator.py`：`SessionRunCoordinator`（会话运行协调器） | 同名方法增加 `only_recoverable=False`；严格分支使用现有会话锁和运行查询，按下述规则校验，再调用原引擎方法 |
| `channel/web/schemas.py`：`WebErrorCode`（Web 错误码） | 新增 `RUN_NOT_FOUND="run_not_found"`、`RUN_NOT_RECOVERABLE="run_not_recoverable"`；复用 `SESSION_BUSY` |

路由行为：

1. 会话不存在返回 404；使用 `get_run(session_id, run_id)` 校验归属，不存在或不属于会话返回 404。
2. 调用严格放弃分支；忙返回 409 `session_busy`，不满足可恢复条件返回 409 `run_not_recoverable`，不返回假成功。
3. 成功重新读取运行和证据，通过 `_run_activity()` 返回 `status="abandoned"`。不能用 `result.error is not None` 判断失败：既有成功放弃结果带有 `cancelled` 原因，应以运行 outcome 判断。

协调器严格分支：

- 先取得原会话锁；锁已占用时立即抛现有 `SessionBusyError`（会话忙异常），不排队等待运行结束后再放弃。
- 在锁内调用已有 `active_run(session_id)` 再次核验：目标必须是当前活动运行、未结束、非等待审批、非等待子任务。状态须与现有活动投影的 `recoverable` 判定一致。
- 不满足时抛新增 `RunNotRecoverableError`（运行不可恢复异常，由会话服务透传，路由映射 409）。校验后在同一锁内调用原引擎 `abandon_run()`。
- 不要在 `edit_session()` 锁内再调用会重新取锁的协调器方法，避免死锁。
- `only_recoverable=False` 保留原语义；不改引擎状态机。沿用现有单进程 Web 的会话锁范围，不扩展为分布式锁。

### 前端

| 文件／对象 | 修改 |
|---|---|
| `api.ts` | 新增 `abandonRun(sessionId, runId): Promise<RunActivity>`，复用 JSON 请求和错误解析 |
| `types.ts`：`MessageExecution`（消息执行视图） | `stage` 联合类型增加 `abandoned`，不增加重复的运行模型 |
| `useSessionWorkspace.ts`：`ConversationView`（会话页面状态） | 新增 `abandoningRunId: string \| null = null`，只用于本次操作互斥和按钮禁用 |
| 同文件 | 新增 `abandon(id, messageId, runId)`；导出该方法，按下述行为更新 |
| `RunActivityPanel.tsx`：`RunActivityPanel`（消息运行过程组件） | 增加 `onAbandon(runId)`、`abandoningRunId` 输入；可恢复卡片增加“放弃本次运行” |
| `App.tsx` | 将放弃回调连接到 Hook；提交期间禁用同一会话恢复、审批、发送等冲突操作 |

`abandon()` 行为：

- 核验目标消息关联该运行，且当前活动状态为 `recoverable`；立即设忙，不提前修改业务终态。
- 成功将响应写入 `activitiesByRunId`，同步活动状态及原消息；移除恢复按钮、停止该运行轮询，释放发送限制。
- `phaseFor()` 可继续将 `abandoned` 映射为已有 `cancelled` 控制阶段，避免扩大全局状态类型；`patchMessageExecution()` 优先根据活动状态显示 `abandoned`，不能被改成“已停止”。`finalStages` 包含它。
- 放弃原因是正常结束说明，不呈现红色模型错误，也不显示成功对勾；显示“已放弃”。
- 409 保留原消息并查询状态；网络中断提示“放弃结果待确认”，查询同一运行，不自动再次提交。失败后释放按钮忙状态，不清空正文、思考或工具记录。
- 用户点击后在卡片原位二次确认：“放弃后不能恢复；已执行的操作不会撤销。”确认后才发请求，不新增全局弹窗。
- 确认期间状态变更时取消确认；活动已结束时禁止请求。重复提交已放弃运行允许返回上述 409，由查询收敛，不要求修改核心幂等语义。

## 3. 审批卡片展示具体操作

### 数据与关联

`channel/web/schemas.py` 的 `RunActivityResponse`（运行活动响应模型）新增：

```python
approval_call_id: str | None = None
```

`app.py::_run_activity()`：仅在当前 `waiting_approval` 状态，查找 `WAITING_APPROVAL` 事件中与当前 `approval_id` 相同的记录，取其 `call_id`。找不到返回 `None`；不能取第一条或最近一条不匹配的工具。

`frontend/src/types.ts` 的 `RunActivity`（运行活动模型）增加 `approval_call_id?: string | null`；`api.ts` 校验字段存在时只能为字符串或 null。其他工具字段和审批接口不变。

### 组件

新增一个文件 `frontend/src/ToolPresentation.tsx`，只放以下小组件及必要纯函数，不建立注册中心：

- `ToolApprovalSummary`（工具审批摘要组件），输入 `tool?: ToolExecution`（现有工具执行模型）。
- `ToolResultView`（工具结果展示组件），输入 `tool: ToolExecution`。

`RunActivityPanel` 用 `approval_call_id` 精确查找 `activity.tools`，将摘要放在批准／拒绝按钮上方：

| 工具名称 | 默认可见内容 |
|---|---|
| `builtin.process.execute` | “执行命令”＋完整 `arguments.command`，等宽、可复制；长命令可滚动查看，不静默省略关键部分 |
| `builtin.files.write_text` | “写入文件（覆盖模式）”＋`arguments.path`；待写入 `arguments.content` 提供折叠预览，不声称已生成 diff |
| 其他工具 | 工具全名＋原始参数 JSON，默认展开；不猜测操作风险或含义 |

字段按实际类型检查。未定位到当前审批工具时显示“审批操作详情暂不可用，请刷新”；禁用批准，保留拒绝与重新查询。不要误用上一条工具的参数。现有引擎仍负责审批有效性。

## 4. 工具结果分类展示

在原 `ToolStep`（工具步骤组件）内用 `ToolResultView` 替换统一原始结果 `<pre>`；保留名称、时间、后端状态、错误和参数入口。

| 工具 | 渲染方式 |
|---|---|
| `builtin.process.execute` | 等宽输出区域、复制按钮；标为“命令输出”，不是实时终端 |
| `builtin.files.read_text` | 路径标题＋纯文本代码区域；文件内容不当成 HTML 或 Markdown 执行 |
| `builtin.files.list_directory` | 路径标题＋原样目录文本；不解析成可点击文件树 |
| `builtin.files.write_text` | 原样结果文字；不展示不存在的修改 diff、回滚或下载按钮 |
| `builtin.web.search` | 成功且可解析时显示既有搜索来源卡片；格式不符合时回退原始文本 |
| 其他工具／解析失败 | 通用纯文本，不报错中断整个消息 |

`SearchSources.tsx`：提取现有内部解析为 `parseToolSearchSources(tool)`，原 `parseSearchSources(activities)` 调用它并继续去重；提取 `SearchSourceList`（搜索来源列表组件）供两处复用。保留当前 HTTP(S) 链接校验和 `noopener noreferrer`，不新增网络请求。

原消息底部搜索汇总继续保留折叠状态；工具卡片展示单次搜索来源。结构化卡片保留“原始结果”折叠入口；本来已是纯文本输出时不再复制一份同样的原始结果。

长结果先展示前 4000 字符并明确标注截断，提供“展开全部／收起”和“复制完整结果”。写入内容预览也使用该限制。数据不截断、不另存一份。

**状态边界：**只使用后端 `status/error`。当前命令工具没有结构化退出码，部分工具把错误写进结果字符串；不得通过文字猜测退出码或宣称业务成功。通用 completed 文案使用“调用结束”，避免把执行返回等同结果正确。

## 5. 删除、保留与样式

- 删除审批卡片“展开工具参数确认后再决定”的笼统提示，改为直接展示精确关联的操作摘要。
- 删除 `ToolStep` 中统一渲染所有工具结果的分支，替换为上述分类组件。
- 保留原始参数、原始结果回退、P0/P1 错误与接收确认、消息内过程及历史查询。
- `styles.css` 只增加命令输出、文件内容预览、审批摘要和原位放弃确认样式；沿用现有卡片、按钮和颜色变量，不新增 UI 库。
- 不新增路径打开、任意本地文件读取下载、附件上传、实时 stdout、退出码模型、diff、回滚或子任务取消。

- 对既有 SSE 审批投影补上关联失效处理：新的 `approval_id` 到来时先清空旧 `approval_call_id`，必须等匹配的活动查询结果才能批准；不能把前一次审批的参数带到本次卡片。

- API 活动结构校验提成私有共用函数，供活动读取与放弃响应复用；未新增另一套运行模型。
- 协调器与 Web 放弃测试合并放在新的跨层测试文件，复用已有 E4 假模型和临时检查点夹具，覆盖同锁验证与真实放弃收口，不执行真实工具。
