# AgentRun 状态机重构开发计划

> 状态：待实施  
> 前置设计：[总体设计](./状态机分层重构总体设计)  
> 实施策略：一个完整目标，按可验证纵向切片迁移；不保留旧状态格式兼容。

## 1. 范围与完成定义

本计划实施 `AgentRun` 单 Run 状态机的已确认设计：联合状态、事件联合类型、action 驱动 Engine、异步 delegation 挂起，以及 `RunStatus` / `INTERRUPTED` 删除。

完成时必须同时满足：

- `AgentRun.state: AgentRunState` 是唯一持久化控制状态。
- Runtime 主路径不再读取 `AgentPhase` 或 `RunStatus` 来决定行动。
- `AgentRunEvent` 只经 `transition()` 消费；`RunEvent` 仍只作审计。
- 所有结束路径经 `Ended(outcome) + FINALIZE` 收口。
- 父 Run 提交 delegation 后变为 `Suspended(DELEGATION)`，子 Run 结果通过独立恢复入口回灌。
- `INTERRUPTED`、旧 phase/status、旧恢复命名与旧 checkpoint 状态字段已物理删除。
- 全部相关测试、文档与搜索验证通过。

本计划不实现新的多节点执行、`ExecutionAttempt`、租约协议或更复杂的 checkpoint 副作用恢复算法。

## 2. 现状与目标映射

| 现有概念/位置 | 目标替代 | 删除条件 |
| --- | --- | --- |
| `runtime/domain/state.py::AgentState` | `AgentRunState`，仍位于 domain state 模块 | 新状态单测与 Engine 主路径通过 |
| `AgentPhase` | `Created | Running | Suspended | Ended` + 局部枚举 | 所有导入与序列化调用归零 |
| `facts.py::RunStatus` | `AgentRun.state` 与 `state.is_ended()` | DTO、仓储、协调器、Port、测试全部迁移 |
| `RunCheckpoint.agent_state` | `AgentRun.state` | checkpoint 只保存 `action` 与恢复数据 |
| `RunCheckpoint.next_action` | `RunCheckpoint.action` | 所有构造、读取、序列化和测试迁移 |
| `AgentAction.WAIT` | `AgentAction.SUSPEND` | 所有等待路径迁移 |
| `AgentAction.HANDOFF_TARGET` 不可达 | `DelegationRequested -> HANDOFF_TARGET` | delegation 集成测试覆盖 |
| `INTERRUPTED` / `retry_interrupted()` | 无状态的 `resume_run()` | 非 Ended + checkpoint 恢复测试通过 |
| `abandon_interrupted()` | `abandon_run()` + `AbandonRequested` | 显式放弃测试通过 |

数据迁移策略：测试/开发 Session 数据清空；仓储只接受新格式。不得添加旧 `phase`、`status` 或旧 checkpoint 的反序列化兼容分支。

## 3. 阶段 0：建立状态机契约与测试基线

### 目标

在替换 Engine 前先冻结纯领域行为，确保后续迁移可由小范围测试定位。

### 修改项

- 重写 `src/dotclaw/runtime/domain/state.py`：定义 `AgentRunState`、四类 mode、局部枚举、`StateTransition`、`InvalidTransition` 和按状态分组的纯 handler。
- 重写 `src/dotclaw/runtime/domain/events.py` 中的状态机输入事件为联合分支；保留并区分审计 `RunEvent` / `RunEventType`。
- 修改 `src/dotclaw/runtime/domain/control.py`：删除 `WAIT`，加入 `SUSPEND`，保留并接通 `HANDOFF_TARGET`。
- 增加 `STATE_TRANSITION_REJECTED` 审计类型；删除 `RUN_INTERRUPTED`。
- 修改 `tests/runtime_v2/test_domain_state.py`，以迁移矩阵逐项测试新状态、事件、action 和非法事件不变性。

### 验收

- 覆盖总体设计 §4.5 的每一条迁移。
- 覆盖错误审批 ID、错误 child ID、Ended 后事件、重复事件均抛 `InvalidTransition` 且原 state 不变。
- 断言状态快照不可变：一次 transition 不修改输入 state。
- `rg -n "AgentPhase|WAITING_|AgentAction\.WAIT" src/dotclaw/runtime/domain tests/runtime_v2/test_domain_state.py` 无旧运行语义命中。

## 4. 阶段 1：持久化唯一状态与 operation node 字段

### 目标

让 `run.json` 保存唯一 `AgentRunState`，并使 checkpoint 保存当前节点 `action` 而非第二份 state。

### 修改项

- 修改 `src/dotclaw/runtime/domain/facts.py`：`AgentRun.status` 改为 `state: AgentRunState`；删除 `RunStatus`。`RunCheckpoint.agent_state` 删除，`next_action` 更名为 `action`。
- 修改 `src/dotclaw/runtime/domain/context.py` 的成功提交意图：由 `target_status` 改为 `target_outcome`。
- 修改 `src/dotclaw/runtime/adapters/run_repository.py` 与 `in_memory_run_repository.py`：序列化/反序列化 `AgentRunState`；活跃 Run 依据 `not run.state.is_ended()`；成功提交校验 `Ended(COMPLETED)`。
- 修改 `src/dotclaw/runtime/adapters/checkpoint_repository.py` 与相关 fixture：只读写新 checkpoint 格式。
- 将 `RunExecution.state`、`RunExecutionView.state` 的类型改为 `AgentRunState`；将局部 `pending_calls` 收敛为 `RunExecution` 执行数据，以便 action 驱动和 checkpoint 恢复共享。
- 删除 `tests/fixtures/runtime/legacy_agent_run_v1.json`、`scripts/migrate_agent_run_v1_to_v2.py` 及仅服务旧状态格式的测试。

### 验收

- 新建 Run、审批等待、成功、失败、取消、放弃均能在 `run.json` 往返序列化。
- checkpoint 不含 `agent_state` / `next_action`，含 `action`、序号和 pending 恢复引用。
- `list_active_runs()` 仅按 `state.is_ended()` 判断。
- 清空测试存储后，所有仓储与 checkpoint 测试通过；不接受旧格式是预期行为。

## 5. 阶段 2：Engine 改为 action 驱动并闭合终态

### 目标

消除 `_drive()` 对 `AgentPhase` 的流程判断，使每次 action 执行结果回灌为 `AgentRunEvent`。

### 修改项

- 重构 `src/dotclaw/runtime/application/engine.py::_drive()` 为“消费 `StateTransition.action` → 执行 → 生成 event → transition”的循环。
- 创建集中但职责单一的 action 执行方法，例如 `_invoke_llm_action()`、`_execute_tools_action()`、`_suspend_action()`、`_finalize_action()`、`_handoff_target_action()`。
- 每次 transition 后先持久化新的 `AgentRun.state` 与当前 operation node 的 checkpoint action，再执行外部副作用；保持既有消息先落盘、审计引用消息的顺序。
- 成功路径先让状态机到 `Ended(COMPLETED)`，再由 `FINALIZE` 使用既有 `SuccessCommitIntent` 完成 Conversation、审计、Run 与 checkpoint 收口。
- 失败、取消、超时和放弃同样先经状态机 transition，再走统一的 `FINALIZE` 终态写入。
- Application 边界捕获 `InvalidTransition`，记录 error 日志并追加 `STATE_TRANSITION_REJECTED`。

### 验收

- `rg -n "AgentPhase|\.phase|RunStatus" src/dotclaw/runtime/application/engine.py` 无控制流命中。
- 最终 LLM 回复后，内存与持久化状态均为 `Ended(COMPLETED)`。
- Engine 不直接 `replace(..., state=...)` 选择业务状态；所有状态变化来自 `transition()`。
- 成功提交故障注入测试仍覆盖 Conversation、完成事件、Run 状态和 checkpoint 删除的恢复顺序。

## 6. 阶段 3：审批、delegation 与显式挂起

### 目标

以 `Suspended` 统一表达正常外部等待，并使 `HANDOFF_TARGET` 真正驱动异步子运行提交。

### 修改项

- 修改审批恢复路径：`resolve_approval()` 读取 `AgentRun.state` 和 checkpoint action；通过 `ApprovalGranted` / `ApprovalRejected` 迁移恢复，不再检查 `RunStatus.WAITING_APPROVAL`。
- 修改 `DelegationPort` 及 DTO：删除 `RunStatus` 依赖，`DelegationResult` 暴露子 Run 的 `AgentRunState` 或明确的 `Ended` 结果。
- 修改 `_delegate()`：拆分为提交 action 和结果恢复 action。提交后产生 `DelegationSubmitted`、持久化 `Suspended(DELEGATION)` 并返回；不得立即把 `result()` 缺失判为失败。
- 新增 `resume_delegation(child_run_id)` 或等价的父 Run 恢复入口：查询子 Run 结果，先写 `DELEGATION_RESULT` 消息，再发送 `DelegationCompleted`，无论子 Run 成败都回到源 Run 的 LLM。
- 将 cancellation 对挂起 delegation 的子 Run 取消保持为当前 cancellation service 的责任。

### 验收

- 审批通过恢复 `EXECUTE_TOOLS`；审批拒绝到 `Ended(CANCELLED)`。
- delegation 提交后，父 Run 持久化为 `Suspended(DELEGATION)`，当前 `execute()` 返回而非等待子结果。
- 子 Run 成功、失败、取消、放弃均生成父 Run 的 delegation result 消息，并回到 `Running(CALLING_LLM)`。
- child ID 不匹配被拒绝、记录 `STATE_TRANSITION_REJECTED`，且不改变父 Run。

## 7. 阶段 4：删除 INTERRUPTED 并迁移控制入口

### 目标

将可恢复性从伪状态迁出，确保未结束 Run 不会被普通消息自动放弃。

### 修改项

- 删除 `RunStatus.INTERRUPTED`、`RUN_INTERRUPTED`、`retry_interrupted()`、`abandon_interrupted()` 和所有仅为它们存在的 CLI、bootstrap、Coordinator 与测试代码。
- 以 `resume_run(run_id)` 替代旧重试入口：前置条件为 Run 未 `Ended` 且存在可用 checkpoint；具体节点恢复继续委托 checkpoint/resume。
- 以 `abandon_run(run_id)` 替代旧放弃入口：构造 `AbandonRequested` 并通过状态机到 `Ended(ABANDONED)`。
- 调整 `recover_session()`：发现非 Ended Run 与 checkpoint，不再改写领域状态；普通提交遇到非 Ended Run 一律 `SESSION_BUSY`，不自动 abandon。
- 更新 `src/dotclaw/main.py`、`bootstrap/session_interaction.py`、`SessionRunCoordinator` 和对应 Protocol/Fake。

### 验收

- 进程重启遗留 Run 的 state 保持最后持久化的 `Created`、`Running` 或 `Suspended` 分支。
- `resume_run()` 使用同一 `run_id`；普通新消息不会使其成为 `Ended(ABANDONED)`。
- 显式 abandon 后才删除 checkpoint、释放 Session 占用并得到 `Ended(ABANDONED)`。
- `rg -n "INTERRUPTED|retry_interrupted|abandon_interrupted|RUN_INTERRUPTED" src tests docs README.md` 无命中。
