## 3. 阶段 A：最小数据契约与持久化

目标：请求受理与取消提交拥有明确且可恢复的事实。

- 实现 domain/cancellation、取消字段序列化、文件名和仓储接口；先同步内存实现。
- 实现 `load/save_cancellation` 的首次受理与 revision 检查；取消请求独立文件，不修改旧运行对象快照。
- 实现 `commit_cancellation` 和恢复，参照已有成功意图模式；不抽出通用事务框架。
- 新增仓储故障点：请求写入后、意图写入后、事件写入后、审批失效后、checkpoint 删除后、run 写入后、记录 settled 后、意图删除前。
- 本阶段只定义 gate 契约，实际取消服务与 Engine 接线在 B 完成，避免数据阶段提前改驱动。所有可观察的状态/事件写入批次和快照读取最终遵守同一 gate；仓储不重复获取非重入 gate。
- 先提供最小 RunChangeNotifier（运行变更通知器）及契约替身，供后续子运行终态等待使用；E 再接入 Web 观察。通知不依赖前端、不承载持久化事实。
- 启动恢复先处理已存在的成功意图；同时出现两种意图视为不变量破坏，拒绝静默选一份。

验收：重复取消同一 request_id；旧 v4 文件可读；各故障点重启后最多一个取消终态事件、无取消后的成功会话投影；请求写失败不被当作 accepted；事件序号连续；取消意图存在时观察服务不可显示已提交终态。

主要测试：扩展 `tests/runtime_v2/test_repositories.py`、`test_e5_success_commit_recovery.py`；新增 `test_cancellation_persistence.py`。本阶段先用最小 fake 驱动，不要求 UI 接通。

## 4. 阶段 B：能力子任务与 Runtime 收尾

前置：A 的接口及恢复测试通过。

- 扩展 CancellationService（取消控制服务）增加 run_operation；唯一注册表持有能力任务，signal 只定向取消它们，不新增第二个执行管理类。
- 实现登记、取消、幂等和句柄查询；Engine 唯一负责取消受理和进度写盘，取消服务不依赖仓储。
- 对模型 complete、工具 execute、上下文准备的外部 await 加包装；把仓储写入从可取消上下文范围分离。
- Engine 动作边界先捕获受控取消/清理失败，再处理普通业务错误；外层驱动保留完成提交的机会。
- `_finish_cancelled` 从最新持久化状态迁移一次，关闭已启动 span，调用 A 的提交协议。
- B接线补全单Run意图查询与恢复两项仓储端口，重试优先恢复原意图而非重造事件。文件/内存实现与相应测试纳入B所有权。
- Engine旧cancel内部入口删除，更新真实调用方和测试；Web使用的cancel_session暂保留str|None到E，E统一切换回执与目标run_id后删除临时返回转换。
- `_finalize_action` 最终检查取消；成功意图落盘后坚持成功恢复；失败/放弃入口遵守同一裁决。
- 会话协调器新增取消补收尾作业；审批、恢复登记与取消请求共享 gate。
- 同一个实现阶段切换真实模型/工具适配器，删除两端口的 cancel。同步修改 Eval 和测试 fake，禁止留下两个任务所有权来源。

验收：模型等待首 token、流式输出、重试等待、工具 await、上下文压缩中均可请求取消；驱动不被用户取消杀死；取消后无下一轮调用；另一个 Session 不受影响；清理阻塞时仍占用 Session；审批竞争无额外工具执行。

主要测试：`test_runtime_engine.py`、`test_llm_proxy_adapter.py`、`test_tool_executor_adapter.py`、`test_session_cancel.py`、`test_recovery_boundary.py`；新增 `test_cancellation_service.py`。用事件屏障覆盖“请求先于注册”“子任务返回同刻取消”“重复取消发生在 finally 中”。同时验证执行器安全链检查顺序未改变。

## 5. 阶段 C：资源实现与进程树

前置：B 的通用取消边界稳定；本阶段可独立验证工具后端，但最终须通过真实 Runtime 链路。

- 命令工具抽出 ProcessSupervisor（命令进程监管器），Windows 与 POSIX 分别完成所有权建立、输出读取、终止与等待。
- 替换双层 proc.kill 清理；覆盖超时与取消竞争、进程自然退出、创建中取消、孙进程持有输出管道。
- 模型代理及各驱动确认请求流关闭、生成器退出、熔断/计数资源释放；取消不能触发自动重试。
- MCP 当前请求取消透传，不能影响共享连接上的第二个请求；明确 remote_unknown，核对 SDK 请求关联能力。
- 核查同步工具：同步 CPU/阻塞调用不能因外层 Task.cancel 立即停止；现有长阻塞处理必须改成可监管异步资源或显式列为不支持即时取消，不能假装清理成功。

验收：运行可控的父/子/孙进程测试，取消返回终态后均不存活且不再写入标记文件；并行无关命令仍存活；Windows 与 Linux/Docker 都验证。Windows 仅验证主 shell 退出不算通过。模型/MCP 本地退出不等于远端撤销，要验证 UI 效果标记。

主要测试：`tests/tools/test_tools_builtin.py`、现有执行器/MCP 测试；新增 `tests/tools/test_process_supervisor.py`，分平台执行并记录跳过项。禁止在没跑的平台声称通过。

## 6. 阶段 D：委派生命周期、关闭与恢复

前置：A/B/C 的取消和资源契约通过。

- 提取 Engine.prepare_run/start_prepared；普通 execute 复用，保证原输入消息和 run.accepted 行为不重复。
- 委派 prepare 创建 Created 子 Run、以 delegation_task_id 持久绑定；父登记后再 start。移除 sleep(0) 作为注册屏障；注入 Session/Task/Run 创建中途失败，验证补偿不留可启动孤儿。
- `list_child_runs` 读取持久关系；父取消覆盖准备中、已启动、挂起、终态子 Run；父等待子终态不等待父恢复回调。
- `result` 使用真实持久事实；`wait_terminal` 的观察取消不向子执行 task 传播。
- Task 按子 Run 真实 outcome 结算，补偿已终态 Run 但 Task 未投影的窗口。
- Host 初始化恢复取消意图与待取消树；未启动子 Run 不自动启动；无法证明命令资源消失时 BLOCKED。
- 实现维护方法 `confirm_cancellation_cleanup` 的严格前置条件与审计；不开放给普通 Agent 工具。
- Host shutdown 先停止接收、请求停止和等待收尾，再关共享 MCP/HTTP/Context；Web lifespan 不再在通知停止之前无限 gather 运行任务。

验收：取消撞上 prepare/start 每个屏障；父→子→孙传播；只取消子不误伤其他分支；子已完成保持原结果；重启可找回关系；Task 不先于 Run 宣称取消；父子互等测试无死锁；shutdown 超时保留诊断不伪造成功。

主要测试：`test_delegation_port.py`、`test_phase2_application_host.py`、`tests/benchmarks/test_delegation_reliability.py`；新增 `test_cancellation_tree.py`。

## 7. 阶段 E：状态快照与 SSE

前置：D 完成，可从仓储可靠判断停止进度与终态。

- 复用 A 的 RunChangeNotifier（变更通知器），补慢观察者和通知合并测试，不引入消息中间件；生命周期由 Host 管理。
- 实现 RunWatchService（观察服务）：短 gate 下快照、先订阅后读、双游标、启动 generation、15 秒兜底重查。
- 在 Engine 完整持久化批次后及取消记录更新后 notify；不要在半完成提交时推送终态。
- 新增 GET 观察路由及响应字段；保留提交 POST SSE，复用活动信息投影，避免两套状态计算。
- 取消 API 增加明确目标 run_id 与回执，处理重复/已结束/成功提交中/不存在。
- 前端删除正常状态的 800ms 全量轮询，增加每 Run 单连接、断流对账与退避、终态幂等及旧连接隔离。
- 把取消元数据转换为少量用户能理解的状态信息，不展示内部锁/任务对象。

验收：工具开始/结束、审批、取消受理、取消完成可被观察；刷新与重连正确；断流不取消任务；旧快照不覆盖终态；缓慢订阅者不阻塞模型；等待审批时不高频请求；游标越界不会永久挂起。

主要测试：`tests/channel/web/test_sse_contract.py`、`test_api_contract.py`、`test_run_steps.py`，新增 `test_run_watch.py`；前端现有工作区测试与新增断流/重复事件用例。

## 8. 最终验收矩阵

| 编号 | 场景 | 必须检查的结果 |
|---|---|---|
| C01 | 模型首 token 前/中途取消 | 流关闭；无后续重试；正常返回取消结果；只有一个终态 |
| C02 | 长命令及后代进程 | 进程树退出，文件副作用停止；刷新仍已取消；新任务可提交 |
| C03 | 重复取消 | 首次请求标识不变；finally 不被第二次取消打断 |
| C04 | 审批与取消竞争 | 取消先受理时工具执行次数为零；过期批准拒绝 |
| C05 | 响应与取消竞争 | 请求先落盘为取消；成功意图先落盘为成功；无两种终态 |
| C06 | 子运行准备/启动/运行/审批 | 所有未终态后代收尾后父终态；无孤儿 Created 自动启动 |
| C07 | 只取消一个 Run | 无关会话、命令、模型/MCP 调用继续正常 |
| C08 | 取消提交任一步崩溃 | 启动补偿，无重复事件/消息，无取消后的成功 Conversation |
| C09 | 磁盘异常/清理阻塞 | 错误可见，不假 202、不假终态、不允许业务 resume |
| C10 | 刷新、断网、慢消费 | 重连拿到权威快照；状态不回退；运行不受订阅生命周期影响 |
| C11 | 正常成功/失败/超时/恢复 | 保持原语义，失败或超时不会无故变用户取消 |
| C12 | Host 关闭/重启 | 请求原因区分；资源关闭次序正确；待取消不会恢复原业务 |

每个完整场景保存：run_id、取消 request_id、相关 child_run_id、请求与终态时间、最终 run/events/checkpoint/取消记录、真实资源检查、前端观察记录。测量原始数据保留，不仅报告通过数量。

验收指标（**目标，不是当前实测结果**）：

- 本机可控假模型/异步工具：取消受理到本地任务退出不超过 1 秒；进程树停止不超过 3 秒。若超过，定位到请求受理、清理或持久化阶段，不直接放宽阈值。
- 已提交状态到本机页面观察不超过 500ms；断流按退避上限报告恢复时间，不混入正常连接指标。
- 观察连接正常的 60 秒运行窗口，前端周期性 `/activity` 请求为 0（首次加载/人工刷新除外）；取消每次仅一次明确 HTTP 请求。
- 未结束本地任务数、未退出受监管进程数、重复终态事件数、取消后新启动能力数均为 0。REMOTE_UNKNOWN 单独统计，不能算远端清理成功。
- Windows 与 Linux 分别执行固定样本至少 20 次，报告中位数、最大值和失败数；不以样本结果推导通用 p99 保证。

## 9. 兼容、切换与删除

数据：旧 Run 无 cancellation.json 等价于未请求取消；无批量迁移。新增事件和准备 checkpoint 为加法，但旧版本程序不理解待取消与 Created 准备语义，**存在未完成新运行/取消意图时禁止直接降级启动旧程序**。回退先用新版本完成收尾并备份；历史文件不删除取消证据来伪兼容。

接口：Web 原取消 URL 保留，新增字段；同版本前端强制发送 run_id。内部 Port 签名一次切换全部生产/测试/Eval 实现，不长期保留两个取消所有者。

删除门槛：

| 旧实现 | 删除前条件 |
|---|---|
| 模型 `_active_calls/current_task().cancel` 路径 | 所有真实和 fake 调用都经过能力子任务执行器；模型取消测试通过 |
| 工具端口空 cancel、适配器等待集合清理式 cancel | 缓存由 clear_run 清理；在途工具与审批测试通过 |
| 委派 submit + sleep(0) | prepare/start 全部调用点切换；准备窗口与重启测试通过 |
| 内存 `_delegated_runs` 唯一关联 | 持久子关系查询与重启取消树通过 |
| Task 提前取消投影 | Run 终态后结算与投影恢复通过 |
| 前端固定 800ms interval | SSE、断流降级和刷新验收通过；保留 GET 快照接口 |

建议按 A、B、C、D、E 的可验证单元组织改动；接口不兼容的子步骤不能作为可发布中间版本。每阶段满足门槛再进入依赖阶段，最终统一验证入口到资源到存储到页面。
