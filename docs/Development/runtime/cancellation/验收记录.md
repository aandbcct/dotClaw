## 用户可见行为与架构

- 停止先持久化请求，能力任务清理后才提交取消终态；模型、进程树、MCP 和线程 I/O 都有明确资源清理边界。
- 能力任务由取消服务唯一持有；Runtime 决策并记录业务事实；协调器持有驱动及补收尾作业。
- 委派先准备并持久登记，再安排子驱动；父等待真实子终态。关闭后不能启动排队业务；活子存在时拒绝放弃父运行。
- 状态通过完整快照和 SSE 观察；正常连接不再依赖 800ms 全量轮询。断流对账后采用 1/2/4/8 秒含抖动退避。
- 取消明确目标 run_id，旧页面不能误停下一轮运行。双游标、Host generation、连接代次保护旧响应和终态。
- 成功/取消提交意图尚未完成时，普通活动查询、SSE、POST 结果和取消回执都不得提前宣告终态；刷新仍能找回，并继续占用会话。
- 正在保存结果时，恢复/放弃被阻止；观察不隐式补偿持久化事实。

## E 最后确认的接口语义

- `load_run_snapshot`（纯读运行摘要方法）不执行恢复；错归属使用稳定 `run_session_mismatch` 语义错误。实际磁盘权限、坏 JSON 不能误报不存在。
- `list_active_runs`（占用运行查询）包含领域非终态，以及有待提交成功/取消意图的摘要终态；完整提交后释放占用。这是存储提交占用规则，不改变四模式纯状态机。
- `RunObservation`（运行观察快照）保留原始领域事实，并有 `committing` 标记；`RunActivityResponse`（页面活动响应）同样包含该标记，用于显示保存中与禁用恢复/放弃。
- `CancellationActivityResponse`（取消进度响应）只暴露请求时间、进度、待清理数量、效果范围与白名单诊断文案，不泄露内部任务或锁。
- Windows 共享读取错误有界重试最多 5 次，永久失败继续抛出原异常；不重试 JSON 损坏和不存在错误，不叠加成多层重试。
