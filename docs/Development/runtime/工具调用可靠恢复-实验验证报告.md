# 工具调用可靠恢复：实验验证报告

日期：2026-11-14。三层验证已完成；结论限于本文版本、故障窗口和受控环境。

收尾核对：2026-11-16。本报告量化实验对应改造后源码 `6fcea1f`；随后 `85622a8` 仅清理废弃路径，已有定向测试通过，没有重测故障矩阵或性能，不将旧结果冒充清理后的新测量。当前开发状态与提交清单见[分阶段执行计划](工具调用可靠恢复-分阶段开发执行计划.md)末尾收尾记录。

核心结论：六个可比恢复窗口，恢复到预期终态从旧版 **60/180（33.3%）** 提升到新版 **180/180（100%）**；新版 600 个故障样本未观察到重复业务效果。正常调用 P50 增加约 310 ms，最终持久文件占用增加 32.4%。这次改造的收益是中断后的安全性和结果保留，成本是更多持久化工作。

## 目标与版本

验证 Issue #51 的审批等待语义与 Issue #41 的调用级可靠恢复，量化恢复收益及成本。工具错误回灌模型、自主纠错、并行工具和外部对账不属于本轮。

| 项目 | 版本与隔离方式 |
| --- | --- |
| 改造前 | `61ad81f7ccad310464d736c2dad39ed8c34a9d35`，独立只读源码工作树 |
| 改造后 | `6fcea1fc654aeca72c601eaedc0a2036ea97d6f5`，独立只读源码工作树 |
| 浏览器验收 | 候选 `2b6a77a`；与最终版仅 Eval fixture 有差异，实际引擎、Web、恢复服务和委派适配器哈希相同 |
| 环境 | Windows、本项目 `.venv\Scripts\python.exe`、本地文件仓储、单宿主单驱动 |

故障和浏览器数据使用独立临时目录，不向用户会话注入故障，不放开网络策略，不访问外部模型。独立本地 HTTP 提供方用于记录请求与外部效果；这证明受控提供方契约下的恢复行为，不代表任意外部服务均支持去重。

## 第二层：真实进程中断与恢复

正式协议：每个适用的场景、版本各 30 次；20 个场景，其中 8 个有双版本样本、12 个仅适用于新协议，计划 840 个有效故障样本。父进程确认持久屏障后强制终止执行子进程，再以新进程调用实际恢复入口。主批 840 次尝试有 839 次有效，另补 1 次有效样本：共 841 次尝试、840 次有效（新版 600、旧版 240）。旧版投影观测另补测 120 次，独立计数，不与主批同窗合并。

指标分别统计安全可恢复完成、正确阻断、不安全重放、重复业务效果、已确认结果复用和持久事实一致性。正确阻断不会计作任务完成。无效故障注入和功能失败分开保存，不能将功能失败剔除分母。

| 新版指标 | 结果 | 具体含义 |
| --- | --- | --- |
| 恢复到预期终态 | 420/420 | 360 completed、60 cancelled；不等于 420 个业务任务全部成功 |
| 未知副作用正确阻断 | 60/60 | 无可靠结果时失败提示核对，没有额外请求或效果 |
| 重试边界正确阻断 | 120/120 | 预算为零、键过期、契约版本改变、执行作用域改变，各 30 次 |
| 已确认结果复用 | 180/180 | 六个结果投影窗口各 30 次，无新增提供方请求，持久结果快照一致 |
| 最终持久一致性判据 | 600/600 | 独立复读 run/messages/events/checkpoint/ledger/提交意图，满足脚本定义的终态、序号及引用约束 |
| 重复业务效果 | 0/600 | 提供方持久计数；SAFE_RETRY 模拟只读，不产生业务效果 |
| 违反四种重试边界的额外重试 | 0/120 | 请求与效果均未增长 |
| 适用恢复耗时 P50/P95 | 744.45/2047.12 ms | 上述 420 个恢复样本，不含故意阻断；为恢复入口计时，不包含完整进程启动/人工操作 |

六个可比恢复窗口逐项如下。旧版四个投影窗口使用修复观测后的独立补测结果；取消窗口用 29 个主批有效样本和 1 个补样，委派窗口用主批 30 个样本。

| 事件写入后 | 0/30 | 30/30 | 冷恢复事件序号冲突 |

另外，外部效果已发生、结果尚未记录的窗口，旧版 30/30 虽然任务显示完成，却各重复一个业务效果；新版 30/30 安全停止并提示核对。外部效果尚未发生的窗口，旧版可继续完成，新版同样保守阻断。这是安全与自动完成之间的明确取舍，不能把两者都包装为完成率提升。新协议专有窗口（账本结果/投影意图清除、审批决议、SAFE_RETRY/KEYED 和重试边界）不虚构旧版等价测试。

### 实验自身的问题与证据保留

1. 初始主批将旧版 NO_AUTO 两窗的预期错误标为 `correct_block`；原始行不改，派生汇总按版本更正为旧行为 `task_completed`，重复效果仍是安全失败。
2. 初始结果快照依赖新版账本，无法公平观测旧版复用；原指标标记 `measurement_invalid`，修复为旧版工具消息身份/正文快照后，四窗各补 30 次。原来的终态、请求和效果事实仍有效。
3. 唯一无效尝试来自实验屏障直接写最终路径，父进程在 kill 前抢读空/半写 JSON。修复实验文件发布为 fsync 后原子替换，保留原样本，再补一例；残留实验子进程已按 PID 核验清理。补样复现的是旧版真实取消冲突。
4. 主批全部落盘后汇总器计数字段错误导致退出；修正汇总器并从原 JSONL 派生报告，没有重跑或覆盖主批。

主批启动脚本 SHA256：`a6a33d490d5521912608d1a987c5fd92a5354b85af5e25ad102ab7032de910b4`。本次实验框架在执行中修正了标签、观测和汇总，逐行记录共出现 8 种脚本文件指纹，**不能声称整个主批使用同一不可变实验脚本**；被测生产源码始终冻结。父运行器使用已加载版本，新启动子进程读取当时脚本，逐行文件指纹不能独自证明父进程已加载代码版本。脚本版本清单留在协议；缺失观测已通过独立补测修正。最终脚本 SHA256 为 `8e213bf6d7e4effd239b677be828cdba52def05d941b81cb35b49ca34925a07d`，后续复现使用入库最终版本。

每个有效样本保留源码路径/指纹、初始与恢复 PID、kill 结果、屏障事实、提供方请求/效果、恢复输出及持久文件。旧版主批重复效果共 60 次（外效后退出 30、消息写入后退出 30）；补测消息窗口另有 30 次，不能把两批相加伪造成同一组样本的重复率。

## 第三层：前端验收与成本

真实浏览器连接独立端口的生产 HTTP/API、运行引擎和文件仓储；仅模型与工具执行使用可控本地替身。

| 场景 | 结果 | 成功工具结果交付次数 |
| --- | --- | --- |
| 普通调用，桌面 | completed | 1 |
| 审批批准 | completed | 1 |
| 审批拒绝 | cancelled | 0 |
| 执行中取消 | cancelled | 0 |
| 安全恢复 | completed | 1 |
| 副作用不确定 | failed，提示核对 | 0 |
| 普通调用，390px 移动端 | completed | 1 |

7/7 通过，浏览器错误 0，各样本观测到的 HTTP 5xx 为 0。审批和可恢复等待状态刷新后仍可操作，终态刷新后仍绑定同一运行。运行 ID、请求状态与工具交付计数见 `validation/frontend/acceptance-summary.json`，完整响应见 `browser-results-final.json`，截图位于 `screenshots/`。

验收发现并修复了运行中 `completed_at=null` 导致前端快照校验失败、审批不可用的问题。另发现移动端侧栏隐藏会话列表的既有问题：相关生产文件在改造前后无差异，本次未修；移动端消息验收采用预选会话，不等于移动端导航验收通过。隔离服务验收后已清理。

正常执行成本按每版预热 5 次、正式 100 次测量，两版交替执行；统计引擎执行 P50/P95 与最终持久文件字节，启动/屏障/终止耗时不混入普通调用成本。

| 指标 | 旧版 | 新版 | 变化 |
| --- | --- | --- | --- |
| 正常执行 P50 | 1227.13 ms | 1537.45 ms | +310.32 ms，+25.29% |
| 正常执行 P95 | 1532.95 ms | 1877.83 ms | +344.88 ms，+22.50% |
| 每样本最终持久文件占用 | 7315 bytes | 9684 bytes | +2369 bytes，+32.39% |

占用指标是结束时文件大小之和，**不是累计写盘字节或 I/O 放大率**；原始脚本字段 `write_bytes` 的命名不应被误读。这是本机本地替身负载，不能直接推断真实网络/模型任务也慢 25%。

## 解释边界

- 本轮只证明实际执行的有限受控样本；不将零重复效果写成无条件 exactly-once。
- 无幂等与外部对账能力的未知副作用仍可能需要人工核对；安全停止是既定边界。
- 未覆盖断电、磁盘硬件故障、多宿主并写、真实互联网服务或真实模型的业务成功率。
- 运行期约束和旧静态验收缺口均保留，不能用最终通过覆盖早期失败证据。
