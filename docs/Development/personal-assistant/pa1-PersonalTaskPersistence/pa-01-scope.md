# PA-01：个人事务管理范围基线

状态：2026-11-17 用户已确认产品范围；尚未实现。本文是本开发点的范围基线，不代表详细接口设计已经完成。

详细设计已落盘：[plan.md](plan.md) 定义实施顺序，[spec.md](spec.md) 是接口、数据与执行规则的唯一详细定义。

后续确认：允许同名事务，页面提交期间防重复提交；编辑、状态变更及删除使用版本检查，冲突时提示刷新，不静默覆盖。采用 PersonalTaskRepository（个人事务仓储接口）和 SqlitePersonalTaskRepository（SQLite 个人事务仓储实现），不聚合成跨业务通用接口。标签等字段在后续真实功能需要时补充。

## 目标与交付边界

第一个开发点交付可手动使用的个人事务管理：领域模型、本地持久化、管理 API 和最小 Web 页面。“第一版”仅指本开发点。

PersonalTask（个人事务）表示需要跟进或完成的事情，不承担笔记、知识库或日历事件职责。事务独立于会话和 Agent 运行，当前按本地单用户管理。

## 已确认的业务规则

- 字段：标题必填；说明、截止时间可选；系统维护 ID、状态、创建时间、更新时间、完成时间。
- 截止时间支持仅日期和具体时刻。日期型在指定日期结束后逾期，时刻型在指定时刻后逾期；逾期是未完成事务的派生展示，不是独立状态。
- 使用应用级时区，默认 Asia/Shanghai；日期型保留日期语义，时刻型保存明确时间点；不做事务级时区设置。截止时间不自动产生提醒。
- 状态：待办、进行中、已完成、已取消。创建为待办；待办与进行中可互转，也可完成或取消；已完成、已取消可重新打开为待办。
- 完成和取消后仍可编辑标题、说明与截止时间，不自动重新打开。完成时保存完成时间，重新打开时清空完成时间。
- 只保存当前状态，不新增完整状态变更历史。
- 提供取消与确认后的永久删除，不提供归档或回收站。
- 当前手工创建不保存来源会话和运行关联；后续对话创建时再增加实际需要的来源关联。事务生命周期不从属于来源会话。

## 页面与应用边界

- 独立“事务”入口；默认展示待办和进行中；可切换全部、已完成、已取消。
- 支持创建、编辑、状态切换和删除；有截止时间的按截止时间升序，无截止时间的排后；展示逾期标识。
- 本轮不做搜索、拖拽、批量操作。
- 页面通过确定性业务服务修改数据，不调用模型。后续个人助手需要具备创建及管理事务的能力，并复用这套业务服务。
- 不顺带改现有启动架构；业务操作不依赖模型，不代表整个应用可以不配置模型启动。

## 持久化决定与当前代码事实

- 新业务使用应用数据目录下独立的本地 SQLite 数据库；保持现有会话和运行存储不变。
- 当前 RunRepository（运行仓储接口）是运行专用协议，包含运行、取消和提交恢复等操作，不能直接用于个人事务。
- 当前 MemoryStorage（记忆存储）已经使用 SQLite，但其表和操作服务于记忆检索；会话则由 SessionManager（会话管理器）读写 JSON。项目没有统一覆盖所有业务的通用存储接口。

## 后续开发边界

Schedule（调度规则）、TaskExecution（事务执行记录）和 Notification（通知）在后续提醒闭环实现，本轮不建空模型或占位接口。后台执行与会话接入均在后续开发点完成。

标签、分类、优先级、子任务和附件不属于本开发点；本范围确认不构成对其具体交付顺序的承诺。

## 验收范围

- 无需选择会话或调用模型即可创建、编辑和管理事务。
- 刷新页面与重启服务后，内容和状态保持一致。
- 完成、重新打开、取消、永久删除按规则生效。
- 覆盖日期型与时刻型截止边界；取消和完成事项不误报为待处理逾期事项。
- 保存失败时页面明确报错，不显示成功。
- 验证持久化、状态流转和 API，并完成真实浏览器创建—编辑—重启—完成—重新打开的交付检查。

实现以本范围基线及 spec.md 为准；本文不重复维护接口签名与内部步骤。
